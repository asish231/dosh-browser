## Real finding: Bing lane serves garbage, waterfall accepts it

Two distinct queries through the auto waterfall returned irrelevant results — first generic "year" dictionary pages, then unrelated adult content — while the waterfall reported success because hits came back. **There is no relevance gate before an engine is declared working.** DDG forced returns correct results for the same queries. Action item: a minimum-relevance check (query-term overlap in hits) before accepting an engine's results in the waterfall.

## Comparison with Lightpanda / Browser Use / Chromium — not run, and why

Not executed from this repository. The project charter (AGENTS.md) forbids it: this repo builds a browser from scratch and must not use, execute, or link an existing browser (Chromium/CDP of any kind, and `research_repos/` projects — which include `browser-use`, `chromium`, `lightpanda`, `WebKit`, `v8` — are reading material only, never executed from `webresearch/`, tests, scripts, or the server). Lightpanda is installed on this machine (`~/.local/bin/lightpanda`, pre-existing Sep 5), but running it as a benchmark lane from inside this repo would violate the charter. A black-box comparison harness must live outside this repo and be run separately.
